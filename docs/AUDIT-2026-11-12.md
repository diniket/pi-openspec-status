# Hardening audit — 2026-11-12

Base: `2b08bce`; branch: `audit/final-hardening-20261112`.
No merge or npm publication was performed. No runtime dependency was added.

## Confirmed defects and corrections

- Reused PR #4's three commits (`db4998a`, `478accc`, `90aeac8`) with attribution:
  archive-only mutations now refresh the no-active count. Its supplied regression test
  contained an invalid regex literal; corrected it so the suite can actually execute.
- Task fences indented up to three spaces were counted as tasks; closing markers with
  trailing text incorrectly ended code examples. Fixed the shared scanner and removed
  the duplicated task-summary scanner. The intentional `##` groups and `- [ ]` format stay.
- Malformed file responses silently became empty text; synchronous read failures escaped
  the Promise handling. Both now produce explicit read errors.
- Malformed directory responses silently became empty listings, and unexpected directory
  entry names could be joined into paths. Reject invalid responses/components before use.
- Truncated directory listings marked unlisted artifacts absent. Missing entries now stay
  unknown, including empty incomplete spec listings and the specs tab.
- Concatenated machine/workspace keys could collide at `:`. Encode the pair unambiguously;
  partial contexts use their object identity consistently.
- Refresh during an index read coalesced onto the old generation. Remove the old cache
  entry on refresh; existing consumers finish safely, and refreshed consumers read anew.
  Validation results cannot repopulate a removed detail generation.
- Child caches had no pruning despite the historical audit's claim. Bound completed
  entries and retain in-flight requests for coalescing.
- Spec traversal could visit thousands of empty capability folders despite the 12-file
  limit. Limit folders too, and mark the listing incomplete.
- Fenced sample requirements and empty scenario headers could produce `structure ok`.
  Ignore fenced examples, require scenario content, respect section boundaries, and reject
  requirements outside delta sections.
- The simplified validator falsely rejected REMOVED/RENAMED and trusted a bare
  `skip_specs` regex as complete validation. Defer these cases explicitly to the CLI.
- Failed polling was silent. Show a stale-data warning and refresh after connectivity
  recovers. Include listing truncation in fingerprints.
- Truncated tasks displayed partial totals without identifying their scope. Add a visible
  partial-content notice. Clear stale `aria-busy` state when rendering tab content.
- Task counts and Tasks view read the same file twice. Reuse the document cache while
  retaining the index's shorter freshness window (regression covers expiry at 31 seconds).
- Disk fixture tests assumed five event-loop ticks were enough. Intermittent null-state
  failures were observed; wait for actual readiness with a two-second assertion deadline.

## External contracts and outstanding verification

Inspected the published `@fission-ai/openspec@1.15.0` sources (validation constants,
validator, requirement-text parser, and metadata schema). REMOVED requirements are names-only;
RENAMED uses FROM/TO pairs; skip_specs requires valid metadata. This panel deliberately
implements a limited structural check rather than embedding the CLI.

Recovered PR #4 through Git's pull ref. Reading its GitHub description/reviews through
`gh pr view` failed: the proxy denied CONNECT to api.github.com with HTTP 403.
The official pi-web.dev website was likewise denied. The accessible published package
`@wang060919/pi-web@1.202610.9` confirms the public file and navigation API shapes used here,
but exposes plugin API v4. It cannot verify the exact API v5 host claimed by this repository.
No claim of complete host compatibility is made. Draft network additions request
api.github.com and pi-web.dev while preserving package-manager presets.

The plugin remains read-only: DOM uses text nodes, links permit HTTP(S) only and set
noopener/noreferrer; it neither writes workspace files nor runs commands. Host workspace
permissions and symlink containment remain host responsibilities. Missing and unreadable
openspec roots cannot be distinguished from a rejected listFiles request by the current
host contract; the existing root-probe limitation remains.

No search/filter/module split was added: at most 40 changes are displayed and no measured
need justified expanding UI scope. No shared-fetch cancellation was added: multiple mounted
consumers share requests; invalidation uses generations without aborting another consumer.
Requests already started can finish after a panel unmounts.

Merge recommendation is conditional on checking the exact PI WEB v5 host and reviewing
this consolidated branch. The local suite/browser harness do not replace that integration
check. GitHub delivery status and final test count are reported in the delivery message.

## Follow-up (same day, second review pass)

An independent review of this branch confirmed the fixes above and found seven residual
defects: an unreadable auxiliary directory could stop the external-change check, the
stale-data warning was erased by any re-render, a completed manual refresh still allowed one
redundant full reload, one anomalous directory entry hid every change, a fenced-only scenario
body and a requirement outside a delta section were reported as blocking errors while the CLI
accepts them (warning), and a fenced-only `## Why` was treated as invalid. All of them are
fixed, with regression tests, in the follow-up commit; evidence, measurements and the
remaining (documented) divergences are in
[REVIEW-FOLLOWUP-2026-11-12.md](REVIEW-FOLLOWUP-2026-11-12.md).
