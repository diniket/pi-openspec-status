## Verdict as given

Not ready to publish, because of three visible behavioural bugs. No security problems: no
writes, no XSS surface, no private host APIs, and the bounds and cache pruning hold.

## Open — high

**1. Stale render after a workspace switch (`:646-652`)** — reproduced.
The guard uses only `#generation`, which increments in `disconnectedCallback` (`:686`) and
not when `#context` changes. Switch workspace while a load is in flight and the result of
the previous workspace passes the guard and is written over the new one, where it stays
until the host happens to render again.
Suggested fix: capture the context and compare it, in `_refresh` (`:646`), `_forceRefresh`
(`:680`) and `OsDashTilesElement._load` (`:1105`):

```js
const ctx = this.#context;
…
if (ctx !== this.#context || !this.isConnected) return;
```

**2. The session label freezes for the life of the page (`:1200-1209`)** — reproduced.
`_render` uses `indexCache.peek()`, which ignores the TTL (`:918-921`), and `indexCache.get`
is only called when `peek` returns `undefined`, i.e. the first time. Nothing else refreshes
that cache. With the TTL expired and a re-render, the reviewer measured **zero** new
requests and the same `P D T S`. A change created after the first load never appears, and
`openspec archive` never updates "Archived".
Suggested fix: expose the entry age and reload when it is stale, and force a
`loadChangeIndex` when the name is missing from a stale cache.

## Open — medium

**3. `activate` is not idempotent and throws (`:1271-1277`).** On a second activation with a
fresh module instance, `customElements.get(tag)` returns the previous constructor, the
`existing !== ctor` check throws, and **no contributions get registered**: panel, tiles and
label disappear until a page reload. The host's own docs and its bundled `workspace-tasks`
panel use `if (!customElements.get(tag)) define(...)` instead. Suggested fix: define only
when absent, never throw.

**4. A request storm on every invalidation, with no rate limit and no cancellation
(`:676-690`, `:405-466`).** `onInvalidate` calls `_forceRefresh`, which bypasses the TTL and
repeats the whole load: up to 122 sequential requests. The host emits `workspace.files` with
`reason: "agent-activity"` on agent activity, and coalescing only covers the in-flight
window. `context.signal` is never used, although `listFiles`/`readFile` accept `{signal}`, so
abandoned loads run to completion. Suggested fix: a minimum interval in `_forceRefresh`, and
one `AbortController` per load, aborted on disconnect and on context change.

**5. Serial loading (measured `maxInFlight = 1`) (`:423-466`).** The per-change `for … await`
does 82-122 round trips in series. Suggested fix: `Promise.all` in batches of 4-6.

**6. Full DOM rebuild on every invalidation (`:699-760`).** `_renderState` clears and rebuilds
the body: no diffing, so hover and focus are lost and the tree flickers. The host's own tasks
panel explicitly avoids this because it resets mobile scroll and can replace a button
mid-click. Suggested fix: skip the rebuild when the state is structurally unchanged.

**7. The session label rebuilds its shadow DOM on every host render (`:1172-1183`).** The
context object is new each time, so the identity check never holds. Suggested fix: remember a
render key and return early when unchanged.

**8. The error box has no limit (`:714-715`).** Up to ~80 error strings joined into one
unreadable paragraph on a half-broken workspace. Suggested fix: show the first three plus
"… and N more", keep the detail in `title`.

**9. A transient error discards the last good state (`:519-545`).** `doLoad` always replaces
`entry.state`, so a failed forced refresh replaces a good list with "OpenSpec read error".
The reviewer notes the test at `test/run.js:239` is named "fallback su ultimo stato" but
**does not verify any fallback** — a misleading name hiding a missing behaviour. Suggested
fix: keep the previous ready state and mark it stale.

## Open — low

**10.** `attachShadow` is unguarded (`:216-226`): a pre-existing closed shadow root makes it
throw `NotSupportedError` from a property setter.
**11.** `safeList` does not normalise the response (`:472-478`): `{ ...undefined }` yields `{}`
and the later `.entries.filter` throws a `TypeError` that reaches the user as a read error.
**12.** `type: "symlink"` is never handled (`:329-345`): a symlinked change directory or
`tasks.md` looks absent.
**13.** `res.binary` is ignored for `tasks.md` (`:490-503`): a binary file reports "no tasks"
instead of "unknown".
**14.** Three minor parser deviations (`:264-313`): fences indented 1-3 spaces are not
recognised (CommonMark allows them, verified: an indented fence counts the checkbox inside);
`- [  ]` with two spaces does not count as pending, inflating the percentage; `* [x]`,
`+ [x]` and `1. [x]` are not counted. Fences with `~~~`, unclosed fences, headings inside
fences, CRLF and `###` were all checked and are correct.
**15.** No size cap of its own in `parseTaskGroups` (`:264`): it relies only on the host's
`truncated` flag.
**16.** `openSpecKey` degenerates to `"undefined:undefined"` when the context is partial
(`:356-358`), sharing one cache entry across different contexts.
**17.** The header comment (`:55-72`) is factually wrong: it says the host exposes no
stylesheet injection API to third-party extensions. A `stylesheet-integration` capability
does exist in this version (`plugin-api.d.ts:372-397`), reachable via `requires` and
`capabilities.resolve`, and the host docs show it. The shadow-root-per-element approach is
still defensible, but the reason should be "we chose to stay self-contained", not "the API
does not exist".
**18.** `scannedAt` is the load *start* time (`:391`), so with 120 serial requests the footer
stamp is seconds old.
**19.** Release hygiene: no README, no LICENSE, no `.gitignore`, and nothing enforced that
`dist` matches `src`. `"private": true` in `package.json` is fine for GitHub but blocks
`npm publish`. `piWeb.plugins[].module` with `browserRoot: "dist"` was checked and is
correct.
**20.** `test/run.js:49` destructures `ACTIVE_TTL_MS`, which the plugin does not export, so it
is `undefined` — a leftover from an older seam.

## Checked and found sound

- **Bounds and DoS**: `INDEX_MAX_CHANGES` is applied in every path (panel, archive index,
  relay scan); measured with 60 active + 60 archived changes: 42 listings and 40 reads,
  `truncated: true`, no growth. Archived changes are only counted.
- **Cache pruning**: all three caches share the 16-entry limit and protect in-flight entries
  (`loadedAt > 0`). No unbounded growth.
- **Coalescing**: correct in both forms.
- **Shadow DOM**: `ensureShadow` is idempotent, `#nodes` prevents a double skeleton,
  `clearShadow` preserves the `<style>`, and the degraded path without `attachShadow` works.
- **Listeners**: the plugin registers no global listener, so there is nothing to leak.
- **Errors are non-explosive**: every read goes through `safeList` or a `try`; "unknown" and
  "absent" stay distinct in every node.
- **Hostile surface**: no `innerHTML`, no `eval`, no `Function`, only `textContent`, so change
  names and file content cannot inject markup. No path traversal. No writes, no CLI, no LLM.
- **Host API**: everything used is public and matches the published types.
- **Hygiene**: no `console.*`, no `debugger`, no TODO, no secrets, no personal paths.

## Note on the fixtures

At review time one fixture was a byte-identical copy of a real private project file, with
hardware details, absolute home paths and a private project name. It has since been
replaced with a synthetic file that keeps the same shape (6 groups, 7 of 14 tasks,
checkboxes inside code fences), and the mock workspace paths were made generic. The
reviewer flagged this and re-checked after the change.
